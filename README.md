# Claris Growblox Autofarm

WindUI script for Growblox, intended to run through Delta. Version 0.1.38.

Version 0.1.38 makes Moving Drops enter the saved source and destination worlds directly. Its only required locations are the Farm Display Box and destination Display Box; a PNB spot and linked doors are unnecessary. Choose **Moving Drops → Item to move → Blocks / Seeds** for the selected crop. Mixed farm boxes can return both types: the selected type is delivered, the other type is held through trips and returned to the farm box afterward. Each trip saves its chosen item, exact new cargo, destination and held companion count across supported world-change reloads. Previously held selected items stay in the backpack. Older profiles default to Blocks and use their PNB block box; Seeds uses the PNB seed box until an explicit Moving Drops destination is saved. Full Rotation still transfers blocks into its dedicated PNB block box and sends seeds into its PNB seed box independently of these standalone choices. Existing profiles and safe transfer checkpoints remain supported.

Version 0.1.37 makes drop collection travel in one direction per occupied row: left to right, down, then right to left. Empty rows do not reverse the next row's entry side. Quick pickups keep moving; delayed replies, partial stacks and cooldowns settle before the avatar walks out of reach, including at low FPS. Full backpacks still require storage travel. A nearby pickup can retry from the avatar's actual supported position when no tile center overlaps it. Full Rotation defers isolated drops with no reachable pickup position, or three settled refusals, and continues collecting and transferring the farm Display Box's blocks before PNB. Deferrals survive reloads and become eligible again on a later visit after five minutes or when the drop moves. Request errors, unsettled pickups and ambiguous storage operations still pause. Existing profiles and checkpoints remain compatible; no new setting is needed.

Version 0.1.36 recovers loose or stored farm harvest while replacement trees grow, so an empty PNB world is not stranded behind a saved maturity timer. Rotation uses a collection-only pass with the Tractor off, gathers matching blocks/seeds and gems, transfers farm blocks and seeds to PNB storage, then keeps that farm scheduled for its real tree harvest. Growing trees are neither broken nor replanted during this stock recovery. When PNB runs empty it checks each waiting farm once for existing harvest, including older saved rotations, and remembers those checks across world-change reloads. Empty seeds/blocks no longer repeat an empty drain every few seconds. PNB also claims nearby leftover drops before declaring supply exhausted. Actual tree harvesting still requires every selected-crop tree to mature, and an active seed-exhaustion drain still finishes its blocks before farm work. Existing configurations remain supported; no new toggle is needed.

New harvest passes still require every selected-crop tree to mature. Diagnostics show the saved harvest stage. Existing profiles and older checkpoints remain supported; no new toggle is needed.

## Features

- **Place & Break:** choose a block from your inventory, place one directly above your saved PNB position, break it, collect nearby loose gems, seeds, and returned blocks, and repeat. Refill from the right Display Box when the backpack runs out. Put seeds in the left Display Box at the configured count, which defaults to 200. Stop when both backpack and block storage are empty.
- **Moving Drops:** move selected blocks or matching seeds from a Farm Display Box to a saved destination Display Box through direct world entry. Mixed source boxes are supported; hold the other item during trips and return it to the farm box afterward.
- **Harvest Drops:** choose Fist or Dear John Tractor, break ripe trees in top-down zigzag order, then collect and store matching blocks and seeds in the same Farm Display Box. Store either stack when full and optionally start Moving Drops afterward.
- **Planting:** fill supported empty tiles with the selected seed across multiple dirt farms. Refill from a dedicated seed Display Box, skip occupied/floating/denied/unreachable cells, and preserve progress across server changes. It never punches obstacles or combines existing trees with another seed.
- **Named configurations:** Save, Load, New, and Delete multiple profiles containing the chosen block, every saved world and tile, the position from which to access each box/door, and timing settings.
- **Full Rotation:** plant every world in the Planting list, recover existing farm drops/storage to supply PNB while trees grow, harvest each ready farm, move its blocks to PNB, replenish planting seeds, and repeat until stopped. Save a harvest box in every farm world and use the PNB seed box for planting stock. Enable **Replant during harvest** to combine harvesting and planting with carried seeds; the later replant step fills remaining spaces.
- **Discord reports:** send stats manually or automatically every 1-1440 minutes, defaulting to five. Include selected block/seed counts from the saved storage boxes in the current world. Reporting runs independently of farming and respects Discord cooldowns.
- **Anti-AFK:** responds to Roblox's idle event while the script is loaded. Disable it in Settings or unload the script to stop it. The setting is saved per profile.
- **World and position recovery:** PNB automatically rejoins its saved world when Growblox sends the avatar to the world picker. It waits for loading/respawn and returns to the breaking spot through reachable floors and platforms. Stop cancels recovery. Rejoin is saved per profile and defaults to On, including profiles from earlier versions.
- **Control and recovery:** one task runs at a time. Turn its toggle Off to restore the game controls. Tasks turn Off on completion or a critical failure. Rotation continues after ordinary seed refusals and transient movement timeouts, saving missed tiles or the interrupted phase for retry. Server confirmations and transfer checkpoints protect storage operations and unexplained inventory changes.

This implementation was traced from the supplied client dump. Offline compilation and mock tests verify the code paths described by their test output. It still needs an in-game test for Delta's debug APIs, actual server acceptance, navigation, and world transfers. Use **Settings → Copy diagnostics** to report the first failure.

## Set up Place & Break

1. Select the block on the **Place & Break** tab. Press **Refresh inventory choices** after obtaining a new block.
2. Arrange the storage row as `Seed box - Empty - Player - Empty - Block box`. Leave the tile directly above the player empty.
3. Stand still on the middle platform and press **Save PNB spot and matching boxes**. This saves the two boxes automatically when the screenshot's layout matches. If needed, stand beside each box and save it separately.
4. Keep each Display Box dedicated to its corresponding item. Mixed boxes are rejected because Growblox's withdrawal action can take every item type in a box.
5. On **Configurations**, enter a name such as `Sugar Cane - Farm 1`, then press **Save profile / Save as**.
6. Turn **Place & Break** On. Turn it Off to end the task. The UI stays accessible through the floating Claris button.

The script walks to saved positions and storage through the game's normal 2D controls. Loose-drop collection itself keeps the player at the PNB spot and targets drops close to the single farming tile. Full block stacks leave excess blocks for later cycles; reaching the seed threshold deposits seeds and frees room. Repeated server pickup refusal stops the task with a diagnostic containing the rejected UIDs, item IDs, and positions. Keep paths reachable and avoid moving the player manually during a task. If a position times out, check the path and save it again.

For the raised dirt setup, save the PNB position while standing on top of the dirt. Keep access to the entrance beside the world lock and the stepping platforms. The planner reads the current collision map, uses entrances only when the game allows walking through them, and avoids harmful blocks. It can move sideways or down to reach a better jump position, then jump back onto the dirt. A stalled route is replanned up to four times within the movement timeout; a sealed or unreachable spot produces a diagnostic.

Recovery checks the picker throughout loading, including when it appears after an inactive exit animation or interrupts a previous recovery. The script uses the same Recent worlds list as the game, selects the first matching entry for the saved PNB world, and uses the saved name if the list has no match or returns an error. Another world at the top of Recent does not replace the saved farming setup. When the picker UI hook is available, recovery recognizes its visibility separately from the internal world name and restores the game's HUD after entry. Copied diagnostics report the picker hook/visibility and Recent selection. Entry is limited to three attempts per recovery; three consecutive interrupted recoveries stop with a diagnostic. Malformed inventory responses get up to three read-only attempts, and a genuine invalid response still stops the task.

**Settings → Anti-AFK** and **Rejoin world and return to PNB** both default to On. Loading an older profile adds these defaults without changing its saved locations. Rejoining applies to Place & Break; Moving Drops retains its transfer checkpoints and existing recovery rules. If Roblox changes servers, the script arms Delta's teleport queue before farming starts. When that function is available, the same GitHub loader resumes the saved farm after arrival. Otherwise, run the loader again and use **Configurations → Resume saved farm**. A different live world is treated as an unexpected change and stops PNB.

Existing profiles and saved locations still work. Collect any drops remaining in the old outer columns manually once; the new loop does not place blocks there. **Settings → Time to wait for drops** now defaults to 0.1 seconds and allows zero. Loaded profiles retain their saved delay, so set this to 0.1 or zero and save again if your old profile uses 0.75 seconds. The game still controls drop readiness; lowering this extra delay does not bypass that wait.

## Collect harvested drops into Farm storage

1. On **Place & Break**, select the harvested block, such as Sugar Cane. The same selected block applies to Harvest Drops and Moving Drops.
2. In the farm world, stand beside a Display Box for the selected block and its seed and use **Harvest Drops → Save Farm storage**. The location is shared with **Moving Drops → Farm storage**, so an existing saved box works. Save your profile after setup.
3. Choose **Harvest method → Fist** or **Dear John Tractor**, then turn **Collect harvest** On. Once every selected-crop tree is fully grown, trees are broken first. The Tractor collects nearby gems while harvesting. Matching loose blocks and seeds, including those already held, are then collected and stored in the same box; any remaining gems are collected as currency. **Respawn to Farm storage** defaults to On; keep it enabled when the respawn door is near the box or turn it Off to walk back.
4. Enable **Start Moving Drops after collection** before starting if you want automatic transport. Save the Farm and destination Display Boxes and choose Blocks or Seeds on Moving Drops first. This option is saved per profile and defaults to Off for older profiles. When collection finishes, Collect harvest turns Off and Moving Drops turns On for the selected transfer. With the option Off, you can start Moving Drops manually afterward.
5. Turn the active task toggle Off to stop. The status shows collection, movement, and storage progress; collected/stashed session totals also appear in Discord reports.

Collection reads the current world's loose-drop list and targets the selected block and its matching seed. It respects drop readiness, retry cooldowns, and backpack capacity. There is no identified server action to move loose drops directly into a Display Box, so collection and verified deposit are separate actions. If distant UID pickups are accepted, the script can stay at the box. If refused, it uses the collision-aware walking/jumping planner to get near the drops and returns to storage as needed. Live pickup reach determines which path is used.

Pickup routes and walking returns to storage search the full world, including distant edge platforms and long open columns. Straight supported walking steps form a single run, with precise stops at destinations, turns, jumps, and landings. Pickup positions must overlap the drop vertically and be less than 0.6 tiles away horizontally. Each occupied collection row runs in one direction, alternating after descending; skipped empty rows do not change the arrival side. Up to eight pickup requests can settle while walking, with inventory room reserved until a batch refresh. Slow replies, partial stacks and refusal cooldowns hold movement before the avatar leaves pickup reach. Storage trips wait for outstanding pickups. A nearby drop can retry from the actual supported position even without a valid tile-center goal. Rotation defers inaccessible drops and continues transferring stored harvest; irregular drops outside farm rows can still need individual approaches, and full backpacks require storage travel. Standalone Harvest Drops reports an inaccessible or repeatedly refused drop as a failure.

Each harvest movement allows up to 90 seconds of travel; pickup waits have their own action timeout, reset on successful collection. Route search yields and checks for Stop or a world change. Keep the saved box and farm platforms reachable. A failed deposit retains backpack items and pauses; automatic transport follows completed collection, with isolated rotation deferrals left for later visits. Expected storage respawns wait for a stable avatar and verify the backpack before depositing. Standalone harvest pauses on unexpected world changes; Full Rotation can return to its saved harvest phase. Pending accepted pickups still settle after Stop, so wait for requests before restarting collection. Harvest Drops collects gems as currency and leaves unrelated crops alone. Fist targets only the selected crop. Tractor uses the game's native harvesting behavior and requires a farm without other seed types. It equips during harvesting rows, removes the tractor during other travel, and restores previous footwear on completion, error, or Stop. Missing growth/equipment hooks pause with a diagnostic.

## Set up Moving Drops

1. On **Moving Drops**, select **Crop to move**. This crop is shared with Place & Break and Harvest Drops; an existing selected crop remains available. Use **Refresh crop choices** after stocking your backpack.
2. Choose **Item to move → Blocks** or **Seeds**. Seeds means the matching seed of the selected crop.
3. Fill the Farm Display Box manually or through Harvest Drops. It may contain the selected blocks and matching seeds together. Stand beside it and press **Save Farm storage**.
4. In the destination world, stand beside its receiving Display Box and press **Save Destination Display Box** on Moving Drops. Source and destination must be in different worlds. You do not need a PNB layout or linked doors for this task.
5. Save the named profile. The crop, Blocks/Seeds choice, both boxes and their standing positions are included in configuration export/import.
6. Turn **Moving Drops** On from either world. It enters the source world automatically, makes direct trips to the destination, then returns to the farm box to finish. Turn it Off to stop.

The script records only newly withdrawn selected items as each trip's cargo. Selected items already in the backpack are retained. If the backpack has no room for the selected item, free up space before starting. Mixed boxes may contain only the selected crop's block and matching seed. The game's withdrawal can return either type first: Moving Drops confirms both counts and keeps the unwanted type, up to the native 200-item stack limit, so subsequent withdrawals have room only for the selected type. For **Blocks**, it delivers blocks and returns held seeds; for **Seeds**, it delivers seeds and returns held blocks. On completion, all held companion items are deposited back into the Farm box. Stop or an interrupted transfer can leave these items in the backpack; the script does not discard them. No selected stock in the Farm box means no withdrawal of the other type.

Until an explicit destination is saved on Moving Drops, old configurations use the saved PNB block box for Blocks or PNB seed box for Seeds. Saving a destination here applies to both choices, so select the intended receiving box when changing tasks. A matching mixed destination box is allowed for standalone transfers. Full Rotation independently keeps its PNB block and seed boxes dedicated; do not fill its block box with seeds. Rotation is unaffected by the standalone item or destination choice.

When direct world entry changes Roblox servers, Delta's teleport queue reloads the GitHub loader and resumes the saved transfer when that executor function is available. The account-bound checkpoint carries the Blocks/Seeds choice, exact cargo and held companion count. If Delta does not expose a teleport queue, execute the loader again after arrival and press **Configurations → Resume saved transfer**.

After a release's first load, the loader reuses its validated main script and WindUI files from `ClarisGrowblox/cache/<revision>` across server changes. A new release downloads its own files; damaged cache files are fetched again. If Delta's file functions are unavailable or cache writes fail, loading continues with ordinary downloads. The small GitHub loader is still fetched to select the current release. Connection indexes the GC snapshot once, then uses candidate lists for the HUD, backpack, Respawn and world picker. Startup skips the full punching/planting function scan for Moving Drops and Harvest Drops. Tasks attach their farming hooks when needed. Transfers proceed as soon as the destination world and avatar are ready, with request timeouts and cargo checkpoints retained. Copy diagnostics includes discovery duration, frame yields, upvalue reads and indexed checks. Executor GC/debug calls, GUI loading and actual world loading can still take time; no live startup duration is guaranteed.

An interrupted storage request leaves a `pickupPending`, `depositPending`, or `seedReturnPending` checkpoint. Check the backpack and both boxes before pressing **Clear saved transfer** and starting again. This avoids repeating a storage action whose result was lost. Normal Stop clears the automatic resume checkpoint; restarting starts a fresh task.

## FPS booster for scattered drops

Turn **Settings → FPS booster: hide floating drops** On when a farm has many floating items. Loose blocks, seeds and gems become invisible; their quantities and pickup positions remain available to automation. Display Boxes and the rest of the world stay visible. Harvest collects selected blocks, matching seeds and gems; PNB collects blocks, seeds and nearby gems.

You can switch it while a task runs. The choice saves to the current session and matching saved task checkpoints, so queued world-change resumes retain it. Save your named profile too if you want the same choice when loading that profile; export/import carries the setting. Newly created drops are hidden on the periodic scan, roughly once per second. Normal Stop keeps the booster active. Turn it Off to see loose items for manual play, or unload the script to restore surviving drop visuals.

**Copy diagnostics** includes the booster state, hidden sprite count and any visual/save errors. This reduces drawing and bobbing work; the native client still manages drop records and pickup processing, and the server still loads the world. The FPS gain on your device needs in-game verification.

## Set up Discord reports

1. In Discord, open the destination channel's settings, choose **Integrations → Webhooks**, create a webhook, and copy its URL.
2. In the script's **Discord Webhook** tab, paste the URL into **Discord webhook URL**.
3. Enter your interval in **Send every (minutes)**, for example `1`, `5`, or `30`. Values from 1 to 1440 are accepted, including decimals such as `1.5`.
4. Leave **Include Display Box counts** On to report the saved block box, seed box, and farm box. Select the block and save these boxes using the existing setup controls. Reports count only the selected block or its seed, including matching stacks in a mixed box. PNB and standalone planting require dedicated storage; the Farm box accepts matching blocks and seeds.
5. Enter **Discord user ID to ping on failure**. In Discord, enable **Developer Mode** under settings, then use **Copy User ID** on your profile. Paste the 17-20 digit ID; a copied user mention is also accepted. Leave it blank to receive failure reports without a ping.
6. Keep **Failure alerts** On to receive task, task-start, script-connection, and automatic-resume errors. This works even with timed reports Off. Only failure messages ping the saved user; Stop, normal completion, and a recovery that succeeds do not ping.
7. Press **Send stats now** to check webhook delivery, then turn **Automatic webhook reports** On for timed progress, completed-task reports, and completed rotation cycles. Enabling starts the interval. Editing the interval schedules the next report from that change; manual sends also restart the interval. Discord's retry delay can postpone a report.
8. Use **Configurations → Save profile / Save as** to keep the URL, Discord ID, interval, and toggles. Webhook controls can be changed while farming; stop the task before saving a named profile. These settings also persist through session saves and config export/import.

Reports include Roblox player name, current world/profile and task, harvest method, Full Rotation's cycle/phase/farm, selected block, backpack blocks/seeds, and session totals for blocks broken, gems collected, trips, blocks moved, harvest blocks stored, seeds planted, trees harvested, harvest seeds collected/stored, and completed rotations. Timed/manual stats also query Growblox level and gem balance; failed or slow queries show **Unavailable**. Work/failure events capture progress at the event time and skip those game queries so a disconnected world cannot hold up an alert. Session totals reset when reloading the script. Backpack and box counts use the client's current data without moving or withdrawing items. Boxes in another world or invalid saved locations show unavailable.

Timed reporting continues while the script is loaded, including when farming is Off or recovering. Turn **Automatic webhook reports** Off to stop timed/completion reports and **Failure alerts** Off to stop failure notifications. Unloading stops future sends; an already sent request can still finish. **Webhook status** shows delivery, last successful send, alert status, queued events, and the next interval. Alerts queue behind outstanding HTTP posts, preserve the original failure snapshot, respect Discord's retry delay, and retry other delivery errors up to three times. A delayed successful reply acknowledges its event without reposting it. Changing webhook settings or importing/loading a configuration clears queued events from the previous settings. These queues are local to the loaded script and are not transferred with config exports. HTTP errors do not stop farming. Delta must expose `request`, `http_request`, or a supported equivalent for delivery.

The webhook URL is saved in the local profile, session, and task recovery files. Keep those files and the URL private. The URL is excluded from reports and copied diagnostics; the project's gitignore excludes the local `ClarisGrowblox` data folder.

## Set up Planting

1. Enter your seed storage world and stand beside a Display Box dedicated to one seed type.
2. Open **Planting → Save seed Display Box**. This saves the box, standing position, and storage world. A box containing seeds also selects its seed automatically. **Seed to plant** shows backpack seeds, the saved selection, available source-box seeds, and the seed related to the selected PNB block. Use **Find seed by name or ID** to find other types. Searches show at most 40 choices and retain your current selection.
3. Enter farm names under **Dirt farm worlds (in order)**, separated by commas, for example `FARM1, FARM2, FARM3`. Duplicate names are removed while preserving order. The storage world must be different from the farm worlds.
4. Turn **Plant seeds** On. The script enters the first farm, plants empty supported tiles, and refills from storage when its backpack runs out. It returns to the unfinished farm after each refill, then moves to the next farm when the current scan is complete.
5. Turn the toggle Off to stop. Named profiles also save the seed type, storage box, and farm list.

Planting requires an empty foreground tile with a solid block or platform directly underneath, matching the native seed placement rule. Doors, air vents, existing trees, and other occupied tiles are skipped; empty air without support is skipped too. Native placement checks still enforce access and reach. The script starts at the top-left supported row and plants while walking toward its other side, then alternates direction down the farm. Full rows skip travel. It confirms up to eight seeds together using server inventory and every planted tile, with brief stops at batch confirmation and turns. Movement eases if running would pass a tile before the next seed is allowed. **Settings → Delay after placement** sets the planting interval with a native minimum of 0.15 seconds; the existing default is 0.2. A slower saved setting still applies. Missed cells or obstacles use precise per-tile movement as a fallback. Planting routes can search the whole world and have up to 90 seconds to reach a tile, allowing detours to distant edge platforms. Access-denied or unreachable supported tiles are counted in Recent activity; a completed scan does not claim those tiles were filled.

After refilling seeds or resuming saved planting, the script returns to the next empty tile in the unfinished row and continues moving planting in that row's saved direction. It may pause once to reach that position; returning through an edge platform no longer switches the rest of the row to per-tile planting. Batch confirmation, turns and genuine route/access obstacles still require pauses or precise movement.

An empty seed box ends the task and identifies the unfinished farm. A mixed box or failed server confirmation stops with a diagnostic. Every attempted tile is saved before planting. An interrupted batch is reconciled from all saved tiles and the server backpack before retrying empty cells; conflicting evidence pauses. Older single-seed checkpoints still work. An interrupted storage withdrawal is not replayed automatically: check the backpack and box, then use **Clear saved planting** before starting again.

Planting saves its farm index before world changes and tracks interrupted seed actions. When Delta's teleport queue is available, the GitHub loader resumes planting after a server change. Otherwise, execute the loader again and use **Planting → Resume planting**. Normal Stop or successful completion clears the planting checkpoint. Settings remain saved.

## Export from an emulator and import on a cloud phone

1. On the source device, open **Configurations → Export config**. This exports the current setup, including changes not yet saved under a named profile. Exporting works while farming runs. Copy the exported text from the clipboard or the **Configuration text** field to your destination device.
2. Run v0.1.29 or newer on the destination device and stop any active task. Open **Configurations**, paste the complete export into **Configuration text**, and optionally enter **Import as profile**. Leaving the name blank keeps the exported profile name.
3. Press **Import config**. The setup is applied and saved locally as that profile, and the session is saved for the destination account. You do not need another Save profile step. Existing profiles with the same name get a `.bak` backup.
4. Check saved locations, seed/block selection, and the farm list, then turn on the task you want. Import keeps tasks Off and clears previous local task-recovery checkpoints; it does not move inventory or transfer an in-progress trip from another device.

For file transfer, Export config also saves `ClarisGrowblox/accounts/<RobloxUserId>/exports/<profile>.json` when file functions are available. Copy that file to the destination device, enter its local path in **Configuration file path**, and press **Import config file**. Existing `ClarisGrowblox/accounts/<RobloxUserId>/profiles/<name>.json` profile files work too. If clipboard or file access is unavailable, the exported text remains in the Configuration text field. Exports include saved webhook settings and the webhook URL.

Configs are portable between Roblox accounts, but saved locations still refer to the original world's tiles. For another account, save its PNB spot and matching left/right boxes, press **Full Rotation → Use PNB seeds for planting**, assign its farm list, and save the harvest box in each assigned farm. Save the result under that account's profile name. Moving the character alone does not update coordinates. Each account needs access to its worlds and its own tractor for Tractor mode. Simultaneous accounts should use separate assigned farms and storage; the script has no shared-work coordination. For standalone Moving Drops, save that account's Farm and destination Display Boxes.

## Configuration files

Profiles are saved in Delta's local `ClarisGrowblox/accounts/<RobloxUserId>/profiles/<name>.json` files. Saving again under a different name creates another profile. Loading a profile changes the script's selected block, saved locations, and settings; it does not move the player.

The current configuration and profile name are also saved automatically to `ClarisGrowblox/accounts/<RobloxUserId>/session.json`, including changes not yet saved under a named profile. The script restores this account-bound session before building the UI after a reload or server teleport. It saves before task/world transitions and checks for setting changes every second. An existing idle script's newest configuration takes precedence during an in-place reload only for the same Roblox user ID. Copied diagnostics show session save/restore failures.

All paths below use the logged-in Roblox user ID automatically. Profiles with the same name on different accounts remain separate, even on a shared cloud-phone filesystem. The immutable code cache stays shared.

The first upgraded load copies legacy root-level sessions and task checkpoints only when their saved user ID matches. It keeps the shared files intact, recovers the active named profile from the owned session configuration, and records migration completion to prevent cleared work from being imported again. Legacy profiles without an owner are not automatically assigned; import them through Configuration file path using `ClarisGrowblox/profiles/<name>.json`. Already-overwritten setup must be restored from an export/backup or resaved for that account.

Saved files are validated before loading. Profile names accept letters, numbers, spaces, underscores, and hyphens. Each save is checked by reading it back; an existing file is backed up as `.json.bak`. Transfer recovery uses `ClarisGrowblox/accounts/<RobloxUserId>/resume.json`, tied to the Roblox account and expiring after six hours.

Automatic PNB recovery uses `ClarisGrowblox/accounts/<RobloxUserId>/pnb-resume.json`, containing the running farm's profile and configuration. It refreshes every two minutes during a running farm and is checked against the account and a six-hour expiry. Normal Stop or completion clears it. A pending server teleport preserves it for the queued loader or **Resume saved farm**.

Planting recovery uses `ClarisGrowblox/accounts/<RobloxUserId>/plant-resume.json`, with the configuration, farm index, refill phase, skipped cells, and any pending seed action. It is checked against the account and a six-hour expiry. Counters such as Seeds planted describe the current loaded script instance.

Rotation recovery uses `ClarisGrowblox/accounts/<RobloxUserId>/rotation-resume.json`, bound to the account and a six-hour checkpoint expiry. It includes configuration/profile, PNB during growth waits, replant progress, completed farms, and harvest deadlines based on server time rather than executor uptime. Each fresh script registers the loader for the next supported teleport, then automatic resume restores the rotation before considering standalone task checkpoints. Running rotations refresh their checkpoint during waits, actions, phase changes, and at least every two minutes while requests are settled. A continuously refreshed checkpoint does not impose a six-hour run limit. See the [rotation guide](README-ROTATION.md) for setup and executor fallback behavior.

## Development

Edit `src/main.lua`, `src/core.lua`, and `src/navigation.lua`, then run from this folder:

```powershell
npm run build
npm test
npm run test:lua
```

The build uses only Node's standard library and the supplied `../WindUI` checkout; no npm installation is required. `tests/run.ps1` uses the existing Lua library at `C:\Program Files\VideoLAN\VLC\plugins\lua\liblua_plugin.dll`. An alternate compatible DLL can be supplied with `-LuaLibrary`. The Lua test runner compiles the complete generated script and loader and executes the offline fixtures.

Version 0.1.38 passes 418 offline checks: 47 configuration/layout/storage tests, 363 generated-runtime tests against mock services/server, six generated-loader tests, and two release checks. New coverage verifies direct transfers with only two boxes, mixed-box seed and block ordering, exact cargo preservation, four inventory reads per trip, companion return, seed-trip world reloads, interrupted storage protection, configuration/UI restoration, and rotation's dedicated destinations. Earlier collection direction, low-FPS pickup timing, farm-stock recovery, maturity, combined planting, Tractor gems, navigation, account isolation, seed-exhaustion draining, FPS, connection, webhook and recovery checks remain passing. These mocks do not establish live speed/FPS, server pickup acceptance, emulator filesystem behavior, account/world permissions, teleport execution or Discord delivery.

Push the rebuilt files, new `releases/<revision>` folder, and updated `loader.lua` together. Do not modify an existing release's files. Keep the same GitHub `loadstring` when updating the project.
